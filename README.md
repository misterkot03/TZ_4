Что бы я дорабатывал дальше:

Пагинация / Load more

Сейчас кнопка `Load more` чисто декоративная.
Если бы было больше времени, сделал бы нормальную пагинацию: рендер батчами из массива/АПИ, чтобы можно было подгружать новые карточки без перерисовки всего списка и при этом не терять выбранные фильтры и текст поиска.

Отделение данных от кода

Сейчас данные лежат прямо в JS. Логичный следующий шаг - вынести курсы в отдельный `courses.json` и подтягивать их через `fetch`.
Так можно будет менять содержимое каталога без правок логики, а при желании - вообще подменить источник на реальный API.

Улучшенная доступность (a11y)

Базовую доступность я соблюдал, но это точно можно докрутить:

* добавить полноценную клавиатурную навигацию по табам (стрелки влево/вправо, Home/End),
* аккуратно пройтись по проекту с Lighthouse / axe,
* добить контрасты, aria-атрибуты и видимые фокус-состояния.

Анимации и микровзаимодействия

Сейчас анимации минимальные, чтобы не выбиваться из ТЗ.
Дальше я бы сделал более плавные переходы состояний (hover / focus / active) для карточек и кнопок и лёгкий fade/slide при смене фильтров. Главное - не превращать это в новогоднюю ёлку.

Автотесты

Отдельно можно покрыть логику фильтрации и поиска юнит-тестами (например, через Jest):
проверять, что для разных комбинаций категории + поискового запроса возвращается именно тот набор карточек, который ожидается.

Обработка пустых результатов

Сейчас при отсутствии результатов просто скрываются карточки.
Я бы добавил нормальный empty state: иконка, текст в духе «по вашему запросу ничего не нашли» и кнопку «Сбросить фильтры», чтобы пользователю не приходилось самому всё очищать.
